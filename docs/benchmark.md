# 对标调研：cs-agent 在开源生态中的位置

> 调研日期：2026-10-04。目的：确保本项目在面试官眼中是"作品"而非"玩具"——办法不是堆功能，而是**站对位置**。

## 一句话结论

不与平台级项目比广度，与官方 demo 级项目比深度。cs-agent 的定位是：**手写内核 + 评测驱动 + 框架对照**——这是应届作品里最稀缺的三件事，也是面试追问中最抗打的三件事。

## 三类对标项目

### 1. 平台级（不追）

| 项目 | Stars | 为什么不追 |
|---|---|---|
| Dify | ~157k | 平台化产品，团队工程，个人复刻=更差的玩具 |
| FastGPT / RAGFlow | 高 | 同上，比拼的是工程广度与生态 |

**正确姿势**：cs-agent v1 用 LangGraph 重构时产出《手写 vs 框架对照文档》，这才是从"会用平台"到"理解平台"的证据。

### 2. 官方 demo 级（核心对标）

**openai/openai-cs-agents-demo**（OpenAI 官方航空客服 demo，38 commits）：
- Triage Agent 入口路由 → **与我们的 IntentRouter 同构**，验证了 v0.1 架构选型方向正确
- 多专家 Agent 分流（订票/退改/座位/FAQ 各一个 Agent）
- **护栏先行**：相关性护栏 + 越狱护栏，在进入主 LLM 前拦截（"写一首草莓的诗"直接拒绝）
- README 里三条**脚本化演示动线**——面试官 60 秒看懂全部能力

**LangGraph 官方 customer support 教程**：订单查询/退款/商品咨询/人工升级——与我们的场景几乎重合，v1 重构时直接对照。

### 3. 个人作品级（假想竞争对手）

OCSAgent、agency-ai-solutions/customer-support-agent 等。调研发现的通病：
- 框架黑盒：LangChain 一把梭，追问内核答不上（**我们的机会**）
- 无评测：连一条测试数据都没有（**我们的机会**：v1.5 评测集）
- README 无演示动线，装不起来（实测有安装失败的案例）

## 差距清单（v0.1 现状 vs openai demo）

| 能力 | openai demo | cs-agent v0.1 | 补齐版本 |
|---|---|---|---|
| 入口路由 | Triage Agent | ✅ IntentRouter（意图+实体+情绪） | — |
| 防御性构造 | — | ✅ 钳位/枚举校验/降级 | — |
| 转人工 | ✅ | ✅ 四条件信号（v0.1 已就位） | v0.5 接管 |
| 输入护栏 | ✅ 相关性+越狱 | ❌ | **v0.5 增补** |
| 工具调用 | ✅ | ❌ | v0.5 |
| 记忆/多轮 | ✅ | ❌ | v0.5 |
| RAG 知识库 | ✅ | ❌ | v0.5 |
| Web UI | ✅ ChatKit | ❌ CLI | v1 |
| README 演示动线 | ✅ 三条 | ❌ | **v1 增补** |
| 评测体系 | ❌（demo 也没有！） | ❌ | v1.5（**超越官方 demo 的差异点**） |

最后一行是关键：**连 OpenAI 官方 demo 都没有评测体系**——v1.5 的意图准确率/检索命中率/转人工率基准，就是我们区别于 99% 个人项目的地方。

## 面试定位话术（v1 README 开篇使用）

> "用 Dify 我一天能搭出同样的东西，但我想知道框架替我做了什么。所以我先手写了 Function Calling 循环、对话记忆和 RAG 链路，再用 LangGraph 重构一遍，两版的取舍写成了对照文档。我还建了 100+ 条的评测集来量化每次改动——大多数同类开源项目连一条评测都没有。"
