# cs-agent 路线图

> 节奏：30 天冲刺（2026-10-04 启动开发）。原则：**每个版本必须可运行、有验收标准**。
>
> **v2 规划修订（2026-10-07）**：吸收外部评审（ChatGPT 对标分析 + RAG 落地困境讨论），
> 核心变更一条——**评测从 v1.5 提前到 v0.6**。理由：没有尺子之前的一切优化
> （换向量库、调 prompt）都无法证明"确实更好"，只会陷入"调 chunk-换 embedding-改 prompt"
> 的无限调优循环。先有基线，再谈升级；每次改动用同一把尺子重跑，失败案例即回归集。

## v0.1 · 骨架与意图路由（10.04）✅

- [x] 仓库初始化：目录结构、配置管理（.env + 配置类）
- [x] 架构图定稿 → `docs/architecture.md`
- [x] 意图识别模块（结构化输出 + 实体抽取 + 低置信度信号）
- [x] CLI 入口 + 无 API 自检测试

验收：命令行输入一句话，正确输出意图 JSON。✅ 实跑通过（qwen-plus）

## v0.5 · Agent 内核（10.06）✅

- [x] @tool 装饰器注册表（get_order_status / get_order_price / check_stock / create_ticket）
- [x] FC 循环迁入主项目（保留 day02 三护栏：max_steps / seen_calls 去重 / 异常回传）
- [x] RAG 链路（内存版：markdown 切块 + 双字滑窗检索 + 引用标注；接口稳定，v1.5 可换 pgvector）
- [x] 多轮对话记忆（messages 跨轮存活）
- [x] 转人工雏形（create_ticket + 情绪/低置信度信号）

验收：多轮对话中能正确调用工具并引用知识库回答。✅ 实跑五场景通过
（含关键场景：退款金额先调工具拿实付 307.2，未心算 384）

## v0.6 · 评测基线（10.07）✅ —— 先有一把尺子

- [x] 评测集 `eval/cases.jsonl`：35 例 6 类场景（正常查询 / 信息缺失 / 歧义表达 / 越权请求 / 无关问题 / 需人工接手），每条标注预期意图、应调工具、是否转人工、知识出处
- [x] 评测器 `eval/run_eval.py`：意图准确 / 工具选择 / 转人工判定 / 检索命中(Top3) / 延迟与轮数
- [x] 基线报告 `docs/eval/baseline_v05.md`——**失败案例全部留档，作为之后每次改动的回归集**
- [x] 修复外部评审发现的 bug：`_seen_calls` 跨轮保留导致合法重复查询被误拦（改为每轮独立）
- [x] Agent 行为契约升级：政策回答带【依据】标注；无依据时明示"需要确认"（不编造）
- [x] 文档状态统一（README 与 roadmap 对齐）

验收：同集重跑数字可复现；每类场景有明确的通过率基线。
